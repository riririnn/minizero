# 5五将棋（Minishogi）環境

5×5 盤の将棋（考案：楠本茂信、1970年頃）。ResTNet 論文の再現で、
**アーキテクチャ比較用の盤**として追加した。動物将棋と同じ役割で、論文の 9×9 囲碁に対応する。
本番の実験は 9×9 将棋（論文の 19×19 囲碁に対応、Attention Map の可視化）。

この環境の設計はひとつの方針で決まっている。

> **ルールは 5五将棋の公式規則に従う。ネットワークから見える形は 9×9 将棋に合わせる。**

前者は 9×9 将棋が本将棋の規則に従っているのと同じ考え方。後者は、ここで測った
アーキテクチャの順位を 9×9 に持っていくために要る。

## 1. ルール（電気通信大学 5五将棋大会の公式ルール）

出典は同大学エンターテイメントと認知科学研究ステーション「5五将棋の遊び方」
（How_to_play_55shogi.pdf）。

初期配置（大文字が先手）。点対称になっている。

```
    5  4  3  2  1
 a  r  b  s  g  k     ← 後手の一段目
 b  .  .  .  .  p
 c  .  .  .  .  .
 d  P  .  .  .  .
 e  K  G  S  B  R     ← 先手の一段目
```

| 駒 | 動き | 成ると |
|---|---|---|
| 玉 `K` | 8方向に1マス | 成らない |
| 金 `G` | 斜め後ろ以外の6方向に1マス | 成らない |
| 銀 `S` | 前と斜め4方向に1マス | 成銀（金と同じ） |
| 角 `B` | 斜めに何マスでも | 竜馬（角＋縦横1マス） |
| 飛 `R` | 縦横に何マスでも | 竜王（飛＋斜め1マス） |
| 歩 `P` | 前に1マス | と金（金と同じ） |

- **敵陣は相手側の一段目だけ**（本将棋は三段）。敵陣に入る手、敵陣から出る手で成れる
- 取った駒は持ち駒になり、空きマスならどこにでも打てる。成駒は元の駒に戻る
- 王手は必ず回避する。回避できなければ詰みで負け
- **禁じ手**：打ち歩詰め、二歩（と金は数えない）、行き所のない駒（歩は敵陣で必ず成る、
  最終段に歩は打てない）。禁じ手は合法手の一覧から除く
- **千日手**：同じ局面（盤面・持ち駒・手番）が4回現れたら終局。基本は**先手の負け**。
  ただし**連続王手の千日手は王手をかけ続けた側の負け**。引き分けが存在しない

### 9×9 将棋との違い（意図的なもの）

| | 9×9将棋 | 5五将棋 | 理由 |
|---|---|---|---|
| 千日手 | 引き分け | 先手の負け | それぞれの公式規則 |
| 手がない（王手なし） | 引き分け | 負け | 同上（本将棋は負け。`mdfolder/known_bugs.md` の注記参照） |
| 手数上限 | 512手で引き分け | 256手で引き分け | 規則ではなく暴走防止。5五の対局は短い |

公式規則を守るのは実利でもある。**外部エンジンと対戦できる。**
論文はアーキテクチャを KataGo との勝率で測っている。5五将棋には Fairy-Stockfish や
UEC杯の参加エンジンがあり、ルールが公式と一致していればこの測り方ができる。
動物将棋にはこの相手がいない。

## 2. ネットワークから見える形（9×9 将棋と同じ）

`shogi.cpp` の `getFeatures()` と `shogi.h` の `convertAZ()` をそのまま 5×5 にした。

### 特徴量 266チャンネル

8履歴 ×（自駒・相手駒・千日手・自分の持ち駒・相手の持ち駒）＋ 手番 ＋ 手数。

| 1履歴あたり | 9×9 | 5×5 |
|---|---|---|
| 自駒 / 相手駒 | 14 + 14 | 10 + 10 |
| 千日手（1〜3回目） | 3 | 3 |
| 自分 / 相手の持ち駒 | 7 + 7 | 5 + 5 |
| 小計 | 45 | 33 |
| **合計（×8 + 手番 + 手数）** | **362** | **266** |

- 駒の並び順は 9×9 の `P L N S G B R K +P +L +N +S +B +R` から桂と香を抜いた
  `P S G B R K +P +S +B +R`。持ち駒は `P L N S B R G` から `P S B R G`
- 持ち駒は枚数をそのまま盤面全体に敷き詰める（正規化しない）。9×9 と同じ
- 千日手の面は出現回数 1〜3 に対応。9×9 と同じで、初出でも 1面目が立つ
- 手番の面は先手番なら 1、後手番なら 0。手数の面は手数 / 512。
  **割る数は 9×9 と同じ 512** にしてある。面の意味を両ゲームで揃えるため
- **後手番では盤を180度回転**させる。9×9 の `r = 8 - r; f = 8 - f` と同じ

### 行動空間 1,725

9×9 と同じ並べ方で、打つ手が先、次に「どのマスから・どの方向へ・成るか」。

```
打つ手    5種 × 25マス                        =  125   action_id 0..124
盤上の手  25マス × 32方向 × 成る/成らない      = 1600   action_id 125..1724
```

方向は 9×9 の順序（上・下・左・右・左上・右上・左下・右下）から桂馬跳びの2枠を抜き、
距離は 1〜4。**マスも方向も手番側から見た座標**で、後手番では 180度回転する。

行動の文字列表記は `5e4d`（移動）、`5e4d+`（成り）、`P*3c`（打つ手）。

### value

`getFeatures()` が手番で盤を回すので、ネットワークが出す value は手番視点になる。
`toFirstPlayerValue()` で探索に返すときに符号を戻す。学習側の教師も手番視点。
どちらも 9×9 将棋と同じ実装（`shogi.h:294`、`ShogiEnvLoader::getValue`）。

**この規約が崩れると value が学習できなくなる**（`mdfolder/known_bugs.md` #1）。
崩れていないことは下の対称性テストで確かめている。

## 3. 検証

ルールの検証は 2026-09-24 に実施し、結果を以下に記録する。検証用スクリプトは
実行後に削除した（ルールは今後変えないため）。再検証が要る場合は書き直すことになる。
対称性テストだけは残してある。符号化は今後も変わり得るうえ、その誤りは
学習を止めないので、テスト以外に気づく手段がないため。

### perft（深さ5）

初期局面から深さ5までの合法手の総数を数え、Fairy-Stockfish のテストスイート
（`tests/perft.sh`）の値と比べた。**完全一致**。

```
perft(1) = 14      perft(4) = 35401
perft(2) = 181     perft(5) = 533203   ← Fairy-Stockfish: 533203
perft(3) = 2512
```

### Fairy-Stockfish との全局面照合

ランダム対局2000局を終局まで進め、**すべての局面で合法手の集合**を
pyffish（Fairy-Stockfish の Python 版）と比べた。

```
games 2000  positions 221806  mismatches 0
rule exercised at  uchifuzume 491  nifu 9513  forced 22867
```

各規則が実際に効いた局面数も数えた。「起きなかったから一致した」ではない。

既知の差がひとつある。Fairy-Stockfish は打ち歩詰めの手を合法手に含め、指した後の詰みを
「詰まされた側の勝ち」と採点する（`position.h` の `checkmate_value`）。UEC のルールでは
禁じ手なので、こちらは合法手から除く。照合ではこの差だけを、実際に
「歩を打って王手になり応手が無い手」であることを確かめたうえで許容する。

### 千日手

指し手の比較では勝敗が見えないので別に確かめた。王手の周期は手で書かず、
pyffish でランダム対局から探させた。

```
PASS  plain repetition, sente loses
PASS  plain repetition: still running one ply before the fourth occurrence
PASS  perpetual check by gote, gote loses
PASS  perpetual check by sente, sente loses
```

**後手の連続王手で後手が負けること**が、例外規定を確かめる唯一のケース。
通常の千日手でも先手が負けるので、先手の連続王手では区別がつかない。

### 対称性（9×9 と同じテストを両方で走らせる）

ある局面と、その盤を180度回して先後を入れ替えた局面は、手番の面を除いて
**同じ特徴量**になり、**合法手の集合も一致**しなければならない。

```
$ PYTHONPATH=build/shogi     python3 scripts/shogi_symmetry_test.py shogi
shogi: 362 channels on 81 squares, turn plane 360
games 60  plies compared 7077  games ended 6  failures 0

$ PYTHONPATH=build/minishogi python3 scripts/shogi_symmetry_test.py minishogi
minishogi: 266 channels on 25 squares, turn plane 264
games 60  plies compared 4995  games ended 35  failures 0
```

**両方が同じテストを通ることが、回転の規約が一致している根拠**になる。
これが 5五将棋で測った順位を 9×9 に持っていける理由。

動物将棋は盤を回転させない作りなので、このテストの対象外。

## 4. 既知の制約

- `getActionFeatures()` は空（MuZero 用。AlphaZero では使わない）。9×9 と同じ
- 局面の設定は SFEN で行う（`setFromSFEN`）。対称性テストがこれを使う

## 5. ビルド

```bash
scripts/build.sh minishogi Release
```

登録箇所は3つ。

```
minizero/environment/CMakeLists.txt   include に minishogi を追加
minizero/environment/environment.h    型定義と env_board_size の既定値（5）
minizero/config/configuration.*       env_minishogi_max_moves
```

# どうぶつしょうぎ環境

3×4 盤の将棋（考案：北尾まどか）。ResTNet 論文の 9×9 囲碁に相当する
「アーキテクチャ比較用の小さい環境」として追加した。

## 1. ルール

| 駒 | 記号 | 動き |
|---|---|---|
| ライオン | `L` | 8方向に1マス |
| きりん | `G` | 縦横4方向に1マス |
| ぞう | `E` | 斜め4方向に1マス |
| ひよこ | `C` | 前に1マス |
| にわとり | `H` | 斜め後ろ以外の6方向に1マス |

- 相手のライオンを取るか、**自分のライオンが相手の一段目に入れば勝ち**。
  ただし入った位置が相手の利きにあれば勝ちにならない
- 取った駒は自分の手番で空きマスのどこにでも打てる
- ひよこは相手の一段目に入ると**必ず**にわとりになる。
  にわとりを取っても、手駒はひよこに戻る
- 同一局面が3回現れたら引き分け
- 反則は無い（打ちひよこ・二ひよことも可）

初期配置（大文字が先手）。点対称になっている。

```
   a b c
 4 g l e     ← 後手の一段目
 3 . c .
 2 . C .
 1 E L G     ← 先手の一段目
```

## 2. 実装の方針

ルールはどうぶつしょうぎ（北尾まどか）の公式規則。
**ネットワークから見える形は 9×9将棋・5五将棋に揃えてある。**
3つは同じ論文で比較する環境なので、盤とルール以外は同じ形にする。

合法手の生成は `breakthrough` の型（配列12マスを総当たり）。将棋の sunfish 由来の
ビットボード一式（25ファイル・26万行）は12マス・132手には過剰なため。

## 3. 設計

### 盤面

`Piece{ PieceType, Player }` の配列12個。`owner_ == kPlayerNone` が空きマス。
`position = row * 3 + col` で、**row 0 が後手の一段目**、row 3 が先手の一段目。
先手（`kPlayer1`）は row の小さい方へ進む。

### 行動空間 132

9×9将棋・5五将棋と同じ並べ方で、打つ手が先、次に盤上の手。

```
打つ手    3種(きりん/ぞう/ひよこ) × 12マス =  36   action_id 0..35
盤上の手  12マス × 8方向                  =  96   action_id 36..131
```

**マスも方向も手番側から見た座標**で、後手番では180度回転する
（`relativeSquare` / `relativeDirection`）。ひよこの成りは到達で自動なので、
成りフラグは持たない。行動の文字列表記は `a1b2`（移動）と `C*b2`（打つ手）。

### 特徴量 146チャンネル

8履歴 ×（自駒5 + 相手駒5 + 千日手2 + 自分の持ち駒3 + 相手の持ち駒3 = 18）+ 手番 + 手数。

```
 0- 4  自分の駒 5種        10-11  千日手（1回目・2回目）
 5- 9  相手の駒 5種        12-14  自分の持ち駒 3種
                          15-17  相手の持ち駒 3種
   144  先手番（先手なら1）  145  手数 / 512
```

**千日手の面は3回目で終局するため2枚。** 9×9将棋と5五将棋は4回目で終局するので3枚。

**後手番では盤を180度回転させる。** これに伴い value も手番視点になるので、
`toFirstPlayerValue()` で探索に返すときに符号を戻す。9×9将棋と同じ実装。

非正方形なので `getInputChannelHeight()=4` / `getInputChannelWidth()=3` を上書きする
（前例: `dotsandboxes`）。

### 終局

```cpp
Player winner_;            // ライオンを取った/入った時点で確定させる
bool is_repetition_draw_;  // 同一局面3回
```

盤面から毎回計算し直すのではなく、**決まった瞬間に記録する**。
トライ勝ちは「入った位置が相手の利きにあるか」を `isAttacked()` で確かめてから確定させる。
千日手は局面文字列（盤面 + 両者の持ち駒 + 手番）の履歴を数える。

## 4. 検証

初期局面の合法手が **4手**（既知の値と一致）。ぞうは斜め前が自分のひよこで塞がれて動けない。

```
4 ['b1a2', 'b1c2', 'b2b3', 'c1c2']
```

**対称性テスト**（`scripts/shogi_symmetry_test.py`）を9×9将棋・5五将棋と同じものを走らせ、
ある局面とその鏡像（盤を180度回して先後を入れ替えたもの）が、手番の面を除いて
同じ特徴量になり、合法手のID集合も一致することを確かめた。

```
dobutsu    146 channels, 12 squares   867手を比較  失敗0
minishogi  266 channels, 25 squares  4995手を比較  失敗0
shogi      362 channels, 81 squares  7077手を比較  失敗0
```

## 5. 既知の制約

- `getActionFeatures()` は空（MuZero 用。AlphaZero では使わない）。9×9将棋と同じ
- 2026-09-24 に特徴量と行動IDを将棋family に揃えたため、**それ以前に学習した
  モデルは読み込めない**（18→146チャンネル、行動IDの並びも変更）

## 6. ビルド

```bash
scripts/build.sh dobutsu release
```

登録箇所は2つ。

```
minizero/environment/CMakeLists.txt   include に dobutsu を追加
minizero/environment/environment.h    型定義と env_board_size の既定値（3）
```

`scripts/build.sh` の対応ゲーム一覧は CMakeLists から自動生成されるので変更不要。
